以下是刚从 X 上检索回来的材料（每条形如 `[m1] 正文`，`m1`/`m2`… 是这批材料在本系统
里的编号，很短、很好抄）。
它们全部发布于最近 {{WINDOW_HOURS}} 小时内（{{WINDOW_START}} 至现在）：
{{RESEARCH}}

你的任务：把这些材料**归成 {{MIN_TOPICS}}–{{MAX_TOPICS}} 个话题**，每个话题是一组在讲同一件事的帖子。

判断一个话题值不值得单独列出来：
1. "为什么是现在"——正在发生、刚有变化、刚出现分歧。已经讨论透了的旧话题不算。
2. 有讨论空间——存在真实的分歧或不确定性，而不是一个人人都同意的结论。
3. 材料里**真的**有支撑。宁可少给几个，也不要凑数。

要求：
1. 直接输出 JSON，不要输出任何解释、前后缀或 Markdown 代码块。
2. JSON 结构必须严格为：
   {"topics": [{"title": "<一句话标题，能被独立理解，简体中文>", "description": "<这个话题在讲什么，一到两句>", "keywords": ["<关键词或实体名>"], "why_now": "<为什么是现在>", "unknowns": ["<这个话题里还查不到、或材料互相矛盾的地方>"], "source_ids": ["m3"]}]}
3. **不要输出任何分数。** 这个话题"有多值得继续看"由系统根据材料里的作者数、
   发布时间、互动计数等真实数据算出来，不由你判断。你给的分不会被采用，
   只会让 JSON 多一个没用的字段。
4. 每条材料只要确实在讲这个话题，就都放进去——同一话题被多个不同作者讨论，
   比一个人发很多条更有意义，而这一点系统会自己算出来。
5. source_ids 只能填上面**真实出现过**的编号（形如 `m3`），逐字照抄。核验不上的引用
   会让这个话题被降分，一条都对不上的话题会被整个丢掉——不要让整组努力白费。
6. 用简体中文写（材料是英文也要写成中文）；专有名词、产品名、模型名保留英文原文。
7. unknowns 是**留白**，不是缺点：查不到就写查不到。宁可写"材料里没有提到定价"，
   也不要跳过这一项或编一个答案。
